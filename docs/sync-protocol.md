# Протокол синхронизации v1

Каждый `/api/v1/` запрос передаёт `X-Protocol-Version: 1`, `X-App-Version: 0.1.0`, `X-Device-Id: <uuid>`. Несовместимый протокол возвращает 426, неверное тело — 400. Все тела JSON, лимит 512 КБ; RAW — до 100 000 символов. Origin ограничен, запросы требуют авторизации, кроме явно локального dev-режима.

## API первой версии

| Метод и путь | Назначение |
| --- | --- |
| GET /api/health | Доступность и режим авторизации |
| POST /api/v1/session | Обмен device-токена на HttpOnly-cookie |
| POST /api/v1/notes | Идемпотентная запись RAW |
| GET /api/v1/notes | Оригиналы персонального хранилища |
| GET /api/v1/notes/:id | Один оригинал |
| PUT /api/v1/vault/files | ПК-агент загружает один разрешённый Markdown-файл зеркала |
| GET /api/v1/vault/files | Метаданные последней выгрузки vault |
| GET /api/v1/vault/search?q=... | До 50 фрагментов Markdown из последней выгрузки |
| GET /api/v1/sync?cursor=N | До 200 событий, nextCursor, hasMore |
| POST /api/v1/sync/ack | Подтверждение cursor; desktop также подтверждает файлы |
| POST /api/v1/reminders | Создание с operationId и baseVersion=0 |
| GET /api/v1/reminders | Все напоминания, включая отменённые |
| PATCH /api/v1/reminders/:id | Изменение с проверкой версии |
| DELETE /api/v1/reminders/:id | Soft cancel; тело сохраняет status=CANCELLED |

AI endpoints отложены вместе с AI bridge: не отправляйте запросы на несуществующие маршруты `/ai`.

## Зеркало vault

`PUT /api/v1/vault/files` доступен только устройству с desktop-ролью. Тело содержит `path`, `content`, `sha256` и `modifiedAt`; путь обязан быть безопасным относительным путём к `.md`, а содержимое ограничено 256 КиБ. ПК-агент допускает только обычные Markdown-файлы внутри указанного vault, исключая скрытые каталоги (включая `.obsidian`), symbolic links, `node_modules` и всё, что больше лимита.

Сервер хранит последнюю версию по пути и append-only предыдущие версии. Зеркало одностороннее: сервер не предлагает API для удаления или перезаписи локального файла, поэтому удаление/изменение файла на ПК не может молча потерять серверную копию. Поиск возвращает путь, hash, версию и короткий фрагмент; полный текст не попадает в логи.

## RAW upload

```json
{
  "id": "00000000-0000-4000-8000-000000000001",
  "deviceId": "00000000-0000-4000-8000-000000000002",
  "text": "  точный оригинал\n",
  "clientCreatedAt": "2026-09-06T12:00:00.000Z",
  "contentType": "text/plain",
  "source": "vault-terminal-web"
}
```

Первое сохранение возвращает 201 `{note, created:true}`, повтор идентичного payload — 200 `{note, created:false}`. Повтор UUID с другим RAW или происхождением — 409; серверный оригинал не изменяется, клиентская версия остаётся в очереди. Метаданные `status`, `serverReceivedAt`, `vaultPath` назначает сервер. API не принимает AI-текст в RAW.

## Cursor и ACK

Событие: `sequence`, `entityType`, `entityId`, `operation=upsert`, `payload`, `createdAt`. Sequence строго возрастает в одной БД. Применение страницы и обновление cursor — одна IndexedDB-транзакция. Приватные API-ответы имеют `Cache-Control: no-store`. События по сущности с неотправленными локальными командами не затирают локальные значения; ACK мутации вернёт актуальную сущность.

Обычный ACK: `{ "cursor": "123" }`. ПК-агент добавляет `notes: [{id, path}]` только после записи файла. Только desktop-роль может подтверждать Markdown. Повтор ACK не создаёт нового события, если статус уже подтверждён. Cursor выше текущего конца журнала отклоняется. Изменение статуса не затрагивает RAW.

## Напоминания

Тело всех мутаций: `{operationId, baseVersion, reminder}`. Первая версия равна 1, каждое изменение увеличивает version на один. Весь reminder проходит общую строгую схему, timezone проверяется по Intl. Receipt записывается в той же транзакции. Повтор operationId возвращает прежний результат; другой payload с тем же operationId отклоняется. Старая baseVersion возвращает 409 и `current` для явного сохранения конфликта.

## Retry

Задержки 1, 2, 5, 10, 30, 60, далее 300 секунд с jitter ±20%. Ошибки сети/401/429/5xx не удаляют очередь. Постоянные 400/403/409/413/426 помечаются blocked и показываются пользователю; автоматические повторы не устранят неверные данные. «Синхронизировать сейчас» обходит время backoff для неблокированных операций, не игнорирует конфликт. У заметки виден SYNC_ERROR, полная ошибка и число попыток находятся в панели синхронизации.
