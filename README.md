# Vault Terminal

Персональный блокнот: **записать сейчас, организовать потом, сохранить оригинал**. Корень репозитория одновременно является Obsidian-хранилищем; эта документация живёт внутри него.

Реализована первая рабочая версия по [спецификации](VAULT_TERMINAL_AGENT_SPEC.md): offline capture → идемпотентная серверная синхронизация → базовые напоминания → доставка в Obsidian. Интерфейс на русском, три темы: терминал, тёмная и светлая классика.

## Быстрый запуск

Требуется **Node.js 24+** и npm. SQLite входит в Node, отдельная БД не нужна.

```sh
npm install
npm run dev
```

Откройте [localhost:5173](http://localhost:5173) — адрес Vite, показанный в терминале. API работает на `127.0.0.1:8787`.

Файл `.env` необязателен для локального запуска. Пример конфигурации: [.env.example](.env.example). Без авторизации сервер запускается только на loopback; открытие в локальную сеть требует настройки защищённого сервера.

В репозитории также зафиксирован `pnpm-lock.yaml`: для воспроизводимой установки используйте `pnpm install --frozen-lockfile`. Все команды `npm run ...` можно запускать как `pnpm run ...`.

## PWA и проверка офлайн-режима

Service Worker включается **в собранной версии**, чтобы не мешать разработке.

```sh
npm run build
npm start
```

Откройте [localhost:8787](http://localhost:8787). Дождитесь первой загрузки, затем установите приложение через меню браузера. Офлайн-запуск требует предварительной загрузки приложения. Manifest и PNG-иконки входят в сборку; внешних шрифтов, CDN и AI-сервисов нет.

1. Откройте собранное приложение онлайн хотя бы один раз.
2. Отключите сеть и создайте несколько записей.
3. Закройте браузер, откройте приложение снова без сети: записи останутся.
4. Верните сеть: очередь отправится автоматически. Статусы доступны через индикатор связи.

Сохранение подтверждается только после завершения **одной транзакции IndexedDB**, записывающей и RAW, и операцию очереди. API не участвует в подтверждении локального сохранения. Черновик до нажатия «Сохранить мысль» ещё не сохранён.

## Что работает

- RAW-заметки с UUID, точным исходным текстом, локальной очередью и экспортом JSON.
- Необязательное название заметки сохраняется первой Markdown-строкой (`# Название`), поэтому одинаково доходит до сервера и Obsidian.
- Голосовой ввод по кнопке: Android открывает системное распознавание речи, браузер использует Web Speech при его наличии. Аудио приложение не сохраняет и не отправляет на сервер — перед Save доступен только редактируемый текст.
- Повторные отправки после таймаута, exponential backoff с jitter, запуск при открытии, online/focus/visibilitychange, периодический retry и Background Sync при поддержке браузером.
- Идемпотентный API; неизменяемый RAW и append-only sync log; SQLite WAL + `synchronous=FULL`.
- Входящие, локальный архив, просмотр полного оригинала, поиск по тексту без интернета.
- Напоминания, в том числе из заметки: создание, редактирование, Done, Snooze, отмена и синхронизация.
- При конфликте напоминания очередь сохраняет локальную версию; пользователь может сохранить её как новую копию. История конфликта включается в экспорт.
- Уведомления, пока приложение открыто, и список пропущенных при следующем входе.
- Терминальная и классические темы, размер текста, CRT, свечение, reduced motion; настройки сохраняются на устройстве.
- ПК-агент: Markdown в `00_Inbox`, подтверждение серверу после записи, восстановление после потерянного ACK, отдельная RAW-копия при конфликте.
- Зеркало Obsidian: ПК-агент по явной команде выгружает только Markdown-файлы на сервер, не читая `.obsidian`, скрытые папки, ссылки, вложения и файлы больше 256 КиБ. Сервер сохраняет прежние версии файлов и даёт поиск по последней копии vault.
- Авторизация устройств, хешированные токены, HttpOnly-cookie для браузера, отзыв устройств и ограничение запросов.

## Проверки

```sh
npm run lint
npm test
npm run build
npm run test:e2e
```

`lint` проверяет типы TypeScript, включая Service Worker. Модульные/интеграционные тесты используют временные SQLite и IndexedDB. E2E запускает отдельный сервер на **8799** и проверяет настоящую PWA в headless Microsoft Edge (Windows). Для Chromium установите браузер командой `npx playwright install chromium` и задайте `PLAYWRIGHT_CHANNEL=chromium`. Тестовые базы и профили лежат в `.test-data`, артефакты — в `test-results`; пользовательский vault тесты не трогают.

Проверено 2026-09-08: TypeScript и production build, тесты сохранности/API/ПК-агента и 6 браузерных сценариев. Включая 10 точных RAW-оригиналов после полного закрытия и повторного запуска Edge офлайн, синхронизацию после восстановления сети, потерянный ACK, экспорт без сети, напоминания, мобильную вёрстку и смену темы. Отдельно проверен Vercel-переходник: заранее разобранное платформой JSON-тело POST сохраняет точный RAW и возвращает подтверждение. PWA готова к установке; ручная установка на реальный Android и системные фоновые уведомления не проверялись.

```sh
npm run seed
```

Seed добавляет одну демонстрационную заметку с фиксированным UUID, повторный запуск безопасен. Автоматически демонстрационные данные не создаются.

## Подключение Obsidian

Выберите **существующую** папку vault, явно задав `VAULT_PATH` в `.env` (пример пути Windows: `F:/Notes/MyVault`). Репозиторий не выбирается автоматически.

```dotenv
VAULT_PATH=F:/Notes/MyVault
SERVER_URL=http://127.0.0.1:8787
DESKTOP_DEVICE_ID=3b4302aa-cd1a-4bb9-844c-9078e24d05cc
```

```sh
npm run desktop:sync
npm run desktop:obsidian-watch
```

Первый вариант выполняет один обмен. `desktop:obsidian-watch` начинает синхронизацию при открытом Obsidian и повторяет её каждые 15 секунд, пока существует `Obsidian.exe`. После закрытия Obsidian сервер не опрашивается; при следующем запуске приложение снова запускает обмен. Для автоматического запуска наблюдателя при входе в Windows выполните один раз:

```sh
npm run desktop:obsidian-autostart
```

Команда создаёт задачу Windows `VaultTerminal Obsidian Sync` с режимом «не запускать второй экземпляр». Она работает и от батареи, а пропущенный запуск выполняет при следующей доступной возможности. Сам наблюдатель дополнительно использует общий блокировщик, поэтому ручной запуск и задача не смогут одновременно синхронизировать один vault.

Файлы получают полное UUID-имя `00_Inbox/<uuid>.md`, YAML-метаданные и **точный RAW-текст** после заголовка. Существующая пользовательская версия не перезаписывается: серверный оригинал сохраняется в `Conflicts/`. Позиция чтения хранится в `.vault-terminal/` как неизменяемые checkpoints. `.obsidian/` и секреты не читаются и не отправляются. Для атомарной публикации файлов нужны hard links (на Windows — NTFS); при неподдерживаемой ФС агент сообщит об ошибке и не подтвердит доставку.

Название vault в настройках веб-приложения используется только для `obsidian://open` и не задаёт агенту путь к диску.

### Выгрузка vault и поиск с телефона

Выгрузка запускается только вручную — автоматический наблюдатель не отправляет весь vault каждые 15 секунд. Так сервер не получает служебные настройки Obsidian и лишние копии файлов.

```sh
npm run desktop:export-vault
```

Команда отправляет разрешённые `.md` из `VAULT_PATH` в серверное зеркало. Она не удаляет серверные копии, даже если файл позднее удалён локально; изменение файла создаёт новую серверную версию. В приложении откройте «Найти в записях» и нажмите «Искать в Obsidian», чтобы получить пути и фрагменты из последней выгрузки.

В Copilot Agent Chat можно написать: **«Выгрузи vault на сервер»**. Умение агента запускает ту же команду и показывает только итоговые числа, без текста заметок в логе.

## Доступ с телефона / размещение сервера

Для доступа вне компьютера подготовлен deployment на Vercel Functions с управляемой PostgreSQL-базой Neon. Локальная SQLite-реализация остаётся для разработки и тестов; production не хранит данные в файловой системе Vercel.

```dotenv
DATABASE_URL=postgresql://... # Neon, добавляется интеграцией Vercel
# Адрес Vercel-проекта и origin нативной Capacitor-обёртки.
WEB_ORIGIN=https://notes.example.com,https://localhost
```

### Развёртывание на Vercel

1. Загрузите репозиторий в GitHub и импортируйте его в Vercel.
2. В проекте Vercel откройте **Storage → Create → Neon**, создайте базу и подключите её к production. Интеграция передаст `DATABASE_URL` в переменные окружения.
3. В **Settings → Environment Variables** добавьте `WEB_ORIGIN=https://<ваш-проект>.vercel.app,https://localhost`. При собственном домене замените первый адрес на него.
4. Выполните Deploy. Перед сборкой Vercel безопасно применяет миграцию зеркала vault: она только создаёт отсутствующие таблицы `vault_files` и `vault_file_versions`, не меняя RAW-заметки. Затем `vercel.json` собирает веб-интерфейс, направляет `/api/*` в Vercel Function и отдаёт SPA для остальных URL. Адаптер Vercel передаёт Hono исходное или уже разобранное тело POST, поэтому pairing и синхронизация не зависают.
5. Скопируйте `DATABASE_URL` из Vercel в локальный `.env` **только на время управления устройствами**, затем выполните `npm run device:add -- Телефон`. Команда создаёт токен и инициализирует схему непосредственно в Neon; не добавляйте этот файл в Git. Vercel не выполняет DDL на холодном старте запроса.
6. Для локальной проверки миграцию можно отдельно выполнить через `npm run db:migrate:vault-mirror`; на production она запускается автоматически во время Deploy. Скрипт создаёт только таблицы зеркала и версий; исходные RAW-заметки не изменяются.
7. В APK откройте «Настройки», задайте HTTPS-адрес Vercel-проекта, скопируйте показанный токен и нажмите «Вставить из буфера», затем — «Подключить устройство». Эта кнопка сама сохранит введённый адрес и проверит, что сессия с сервером действительно работает. Поле токена отключает автокоррекцию и не сохраняет введённое значение.

После подключения можно удалить `DATABASE_URL` из локального `.env`: APK и Vercel работают без включённого ПК. Для ПК-агента добавьте также `SERVER_URL=https://<ваш-проект>.vercel.app`, `DEVICE_TOKEN` и `VAULT_PATH` в локальный `.env`.

```sh
npm run device:add -- Телефон
npm run device:add -- ПК --desktop
```

Команда показывает токен один раз. В браузере вставьте клиентский токен в настройках. Он обменивается на HttpOnly-cookie сессии и не записывается в IndexedDB/localStorage. Сессия живёт 30 дней; исходный токен остаётся действующим до отзыва. Для ПК-агента сохраните desktop-токен в локальном `.env` как `DEVICE_TOKEN`. Установка не требует ChatGPT/OpenAI-токенов.

```sh
npm run device:revoke -- UUID_УСТРОЙСТВА
```

Отзыв блокирует токен и все сессии устройства. При смене адреса сервера уже отправленные заметки остаются локально, а новые и ещё не отправленные операции используют новый адрес; автоматического переноса всей истории между серверами нет. Для браузерной cookie-сессии используйте same-origin deployment; сторонние cross-site cookies могут блокироваться браузером.

## Android APK

Готовый APK: [VaultTerminal-debug-0.1.9.apk](artifacts/VaultTerminal-debug-0.1.9.apk). Это debug-сборка для личной установки, подписанная Android Debug certificate; Google Play её не принимает. Android 7.0+ (API 24), target SDK 36.

Перед установкой перенесите APK на телефон и подтвердите установку из этого источника в настройках Android. При обновлении этой же debug-сборки Android сохранит данные приложения; установка release-сборки с другой подписью потребует удалить debug-версию, поэтому сначала экспортируйте RAW в настройках приложения.

APK содержит весь интерфейс, IndexedDB и очередь, поэтому запись доступна сразу и без сервера. Кнопка «Надиктовать» открывает системный диалог Android: распознанный текст возвращается в черновик и сохраняется только после явного нажатия «Сохранить мысль». В настройках приложения укажите **HTTPS-адрес** развёрнутого сервера, нажмите «Вставить из буфера» для device token и подключите устройство — отдельно сохранять адрес не нужно. `localhost` телефона не является этим компьютером. Для production добавьте `https://localhost` к `WEB_ORIGIN` вместе с адресом веб-приложения, как в конфигурации выше: это origin нативной Capacitor-обёртки. Production-сессия использует `Secure; SameSite=None` cookie, а Android WebView явно принимает её для Vercel; сервер отклоняет изменяющие запросы с Origin вне этого списка.

Экспорт на Android записывается в `Documents/VaultTerminal/` и открывает системное меню «Поделиться». Напоминания используют системный Android `AlarmClock`; после срабатывания foreground alarm service самостоятельно запускает зацикленный системный alarm-звук, повторяющуюся вибрацию и heads-up/полноэкранное уведомление, поэтому не зависит только от звука notification channel и работает при закрытом Vault Terminal. После установки откройте «Напоминания» или «Настройки» и нажимайте «Включить» после возврата из каждого системного экрана, пока напротив уведомлений, точного времени и всплывающего окна не появится «да». Сначала нажмите «Проверить звук сейчас», затем «Проверить через 15 секунд» и закройте приложение. Тест автоматически прекратится через 30 секунд; обычное напоминание останавливается кнопкой Done/Snooze. Проверка и обычные напоминания не требуют сервера. Нативный доступ к выбранной папке Obsidian через SAF ещё не реализован.

Новая сборка:

```sh
npm run android:apk
```

Скрипт использует Android SDK, уже найденный в Unity, и локальный JDK в `.android-build`; он выполняет web build, Capacitor sync, debug assembly и `apksigner verify`. Для нового релиза потребуется отдельный signing key, безопасно сохранённый вне репозитория.

## Сохранность и ограничения версии 0.1

- Нажмите «Скачать JSON» в настройках, чтобы забрать RAW, архив, напоминания, очередь и сохранённые конфликты. Автоматического удаления данных и кнопки очистки локальной БД нет.
- IndexedDB переживает закрытие браузера, но пользовательская очистка данных сайта/приватный режим/эвикция браузером могут удалить локальные данные. Доступен запрос постоянного хранения; регулярно экспортируйте оригиналы. Импорт экспорта через интерфейс — следующий этап.
- Сделайте резервную копию серверной SQLite при остановленном сервере (включая `-wal`/`-shm`, если они остались). Перед изменением схемы сначала создайте backup. История миграций: `schema_migrations`, текущая схема: [schema.sql](packages/db/schema.sql).
- В закрытом Android APK работает системный будильник. В браузерной PWA фоновый будильник всё ещё не обещается без Web Push; список просроченных напоминаний останется в приложении.
- Codex Agent Chat в Obsidian может отвечать по локальному vault напрямую. В приложении доступен поиск по последнему серверному зеркалу Markdown; полноценная асинхронная AI-очередь Ask Vault, ответы в приложении и AI-сортировка ещё не реализованы.
- Порог классификации появится вместе с AI-адаптером; сейчас настроек неработающего AI нет. Ни RAW, ни сохранение не зависят от будущего AI.
- Архивирование относится только к текущему устройству. Мягкое удаление RAW и управляемый retention будут отдельной явной операцией; сейчас RAW API удаления не имеет.
- Локальное подтверждение не равно серверному backup: различайте статусы «В очереди», «На сервере» и «В Obsidian».

```text
apps/server/        Hono API и раздача собранного приложения

scripts/           dev/build, seed, управление устройствами
tests/             проверки сохранности и браузерные сценарии
docs/              архитектура, протокол и модель угроз
```
